# Opportunities & Proposals: supplier-side flow (Sathi's notes, Oct 2026)

Applies to all three supplier user types: CROs, scientists and manufacturers.
Source for the Opportunities & Proposals case study. Not published as-is.

## Core rule
The supplier never talks to the customer directly. The Scimplify admin is the mediator:
it approves, rejects and forwards every action, handles pricing and quoting, and gets the
customer's confirmation before passing anything back to the supplier.

## Opportunity module
1. The user opens the Opportunity module and sees the listed opportunities.
2. Clicking an opportunity card opens its details.
3. If it suits them, they submit a proposal to the customer (via the admin) and wait for a reply.
4. Two opportunity types:
   - **Catalogue:** generated from the products in the user's profile; the admin portal shortlists
     relevant opportunities and shows them in the Opportunity module.
   - **Capability:** the user completes a profile of their capabilities; the admin analyses it,
     shortlists suitable opportunities and shows them.
5. Access:
   - **Exclusive projects** (premium access): shown only to selected users.
   - **Open projects:** shown to the 100 onboarded users (CROs, scientists, manufacturers).
6. Filters: project type (catalogue / capability), industry, geography, required certifications,
   proposal deadline.

## Proposal module
7. A submitted proposal appears in the Proposal module.
8. Dashboard: proposals sent, quotes accepted, proposals dropped or cancelled, purchase orders issued.
9. Beside the dashboard, a list of all proposals; search, sort by date (today, this week, this month)
   and by type (catalogue / capability).
10. Each proposal is a card. Opening it shows the linked project, the proposal details and the next
    stage, "Talk to an expert".
11. Stages: Submitted → Quote submitted → Quote accepted → Purchase order issued.
12. Talk to an expert: the user requests a meeting; a Scimplify expert schedules it. If the user
    can't schedule, a representative contacts them to arrange one within 24 hours.

## Admin side (mediation)
13. The admin portal receives the proposal and can schedule a call, request a discussion summary,
    or mark the proposal complete.
14. Discussion summary: the admin asks the user for quantity, price, shipment terms, packaging and
    payment terms. The user may withdraw or continue; if they continue, the admin marks the
    discussion complete and the proposal moves to the next stage.
15. The proposal goes to the customer, who may suggest a price for the requested quantity. Through
    iterative discussion a quote is finalised. On quote submission the admin can reject, accept or
    request revisions.
16. Revisions: the user can see every version of the quote as the admin updates it.
17. When the final version is submitted, the user views and accepts the revised quote.
18. After acceptance, the admin uploads the purchase order, which the user can see.
19. The project then starts and moves into Project management (already a case study).
